# Arch packaging layout

This template keeps two PKGBUILDs because they have different source inputs:

| Path | Use | Source | Checksum |
| --- | --- | --- | --- |
| `local/PKGBUILD` | `make build` from the working tree | generated local archive | injected temporarily by the build script |
| `ci/PKGBUILD` | tagged release | GitHub tag archive (`${url}/archive/refs/tags/v${pkgver}.tar.gz`) | generated by `updpkgsums` in CI |

The package metadata and `check()`/`package()` behavior must remain equivalent.
The source and checksum definitions are intentionally different. Do not commit
generated `sha256sums`, `src/`, `pkg/`, archives, or packages.

`common/functions.sh` normalizes the extracted source directory. GitHub creates
`<repository>-v<version>`, while the local archive uses `<pkgname>-<pkgver>`;
both are presented to the PKGBUILD as `${pkgname}-${pkgver}`.

## Generated themes

`tools/sh/new_theme.sh` sets `pkgname`, `pkgdesc`, `url` and the payload file
names for a new theme. Both PKGBUILDs receive the same metadata, so
`tools/sh/validate.sh` keeps them in sync. Only the `source` and `sha256sums`
lines differ between the two files, as described above.

If you change metadata by hand, update both PKGBUILDs and run:

```sh
make validate
```

To inspect metadata without building:

```sh
makepkg -p packaging/arch/ci/PKGBUILD --printsrcinfo
makepkg -p packaging/arch/local/PKGBUILD --printsrcinfo
```
